# W1D1 测验审校报告

审校范围：`notes/W1D1-quiz.md` 与 `notes/.answers/W1D1.md`。结论基于题面与答案的静态审校，未修改既有文件。

## 总体结论

- 测验覆盖了渲染与提交时序、render 纯度、props 不可变性，以及 state 按树中位置和类型保留这三个 W1D1 的核心心智模型。三题都要求解释原因或修复代码，整体以理解为主，而不是单纯记忆 API。
- 标准与分值存在一个明确的不一致：满分为 7 分，而“≥ 6 分（约 80%）”实际是 85.7%。若标准确为至少 80%，应设为 ≥5.6 分；在整数计分下应明确采用 6/7 的通过线，或调整总分与题目配分。
- 题面没有直接给出结论、关键术语或正确代码，因此没有明显的答案泄露。答案文件标明“答题前不要看”，隔离方式合适。
- 判卷答案总体完整，但第 1 题的 DOM 查询范围、第 2 题的 StrictMode 前提，以及第 3 题的状态来源可再写得更严谨。

## 第 1 题：预测输出

**考查点**：render 发生在 commit 之前；render 中读取 DOM 只能观察到上一次已提交的 DOM；首次提交前目标节点不存在。

**评估结论**：

- 这是一道理解题。作答者必须将两次 render 与两次 commit 的时序联系起来，不能只背诵 `querySelector` 或生命周期 API。
- 参考答案的 `undefined`、`A` 及原因与题设的单一目标 `h1` 相符，给分点也能覆盖结果和机制。
- 严谨性缺口：`document.querySelector(h1)` 查询的是整个文档的第一个 `h1`，题面没有显式保证页面没有其他 `h1`。在该隐含前提不成立时，输出不确定。
- 答案提到 Effect/ref 回调是有用的延伸，但不属于本题要求；不会泄露其他题答案。

## 第 2 题：解释现象

**考查点**：props 是输入而非可在 render 中修改的数据；`reverse()` 的原地变异；StrictMode 通过重复调用暴露不纯 render；复制后再反转。

**评估结论**：

- 题目同时要求解释开发/生产差异并写出修复，能有效区分“知道 `reverse`”和理解 render 纯度及共享引用后果的学习者。
- 参考答案完整覆盖原地修改、StrictMode 双调用、生产环境交替翻转和两种无变异修复写法，3 个评分点与题目目标匹配。
- “StrictMode 每次渲染调用 `Feed` 两次”表述过宽。应限定为开发环境中 StrictMode 为检测不纯渲染而进行的额外 render 调用；不要把它理解成所有 render 都有可依赖的固定调用次数。就本题给定现象与假设而言，双次翻转的推理成立。
- 题干已明确 `reverse()`，这属于设置真实陷阱所需信息，不等于泄露“必须复制数组”的答案。

## 第 3 题：预测 state 是否保留

**考查点**：state 归属 React 树中的组件位置；同位置同组件类型时复用；祖先元素类型改变导致子树重建；JSX 条件分支的书写位置不决定 state 身份。

**评估结论**：

- 题目要求分别预测两种近似 JSX 的行为并说明原因，直接检测 state 身份模型，不依赖记忆某个 Hook API。
- 参考答案的 A 为 `n=3`、B 为 `n=0`，以及“位置 + 类型”的解释完整且配分合理。`key` 的延伸说明正确，但超出 W1D1 的核心评分范围。
- 题面应明示 `fancy` 的切换来自持有 `Counter` 的父组件，且该父组件本身不被卸载；否则读者可能追问切换是否伴随更高层重挂载。该假设通常可由上下文推断，但写明会让题目自足。

## 可选改进（最多三项）

1. 将通过规则改为“满分 7 分，≥6 分通过（85.7%）”，或重设总分/配分使整数阈值准确对应 80%；不要同时写“≥6 分”和“约 80%”。
2. 第 1 题改为用组件自身的 ref 所指向节点，或在题干补充“页面中没有其他 `h1`”，消除全局 `querySelector` 带来的输出歧义。
3. 第 2 题的答案把 StrictMode 的“双调用”表述为开发期的不纯 render 检查，并在第 3 题补充父组件未卸载的前提，避免把示例现象误读成通用且固定的运行时保证。
